# Классы моделей

[Главная](../../README.ru.md) · [English](../en/model-classes.md) · [Установка](installation.md)

> Граница версий: интерфейс относится к текущим исходникам разработки в `main`. Неизменяемый опубликованный тег `v0.41.0a1-r152-v21` сохраняет два прежних ограниченных маршрута. Обновление документации не заменяет и не переподписывает этот архив.

## Постоянный запрос, заменяемая реализация

Исследовательский запуск выбирает **класс модели**, а не закреплённую в коде пару поставщика и модели. Оператор сопоставляет класс с конкретными поставщиком, моделью и уровнем рассуждения в `config.yaml` выбранного экземпляра Hermes. Обновление набора моделей требует изменения настроек, а не исследовательского кода или формулировок вопросов.

Имена классов задаёт оператор. `economy`, `balanced`, `advanced` — примеры обозначений маршрута, а не удостоверенные уровни качества, неизменный перечень поставщиков или служба автоматического ранжирования. Можно задать класс `vision`, если выбранная модель Hermes и процесс действительно обеспечивают нужную возможность. Само имя класса этого не доказывает.

## Контракт настройки

Замените все обозначения `your-*`/`another-*` идентификаторами, которые поддерживает настроенный Hermes. Авторизация поставщика и настройка пользовательского адреса службы остаются обязанностями Hermes.

```yaml
research:
  default_model_class: balanced
  model_classes:
    economy:
      provider: your-provider-id
      model: your-current-small-model-id
      reasoning: low
    balanced:
      provider: your-provider-id
      model: your-current-general-model-id
      reasoning: medium
    advanced:
      provider: another-provider-id
      model: your-current-reasoning-model-id
      reasoning: high
```

- Имя класса соответствует `[a-z][a-z0-9_-]{0,31}`.
- Каждый класс содержит ровно `provider`, `model`, `reasoning`. Нужен явный канонический идентификатор поставщика Hermes; `auto` и адреса служб в поле модели не принимаются. Адреса настраиваются средствами Hermes.
- Синтаксис уровня рассуждения соответствует Hermes: `none`, `minimal`, `low`, `medium`, `high`, `xhigh`, `max`, `ultra`. Выбранная пара поставщика и модели должна поддерживать этот уровень.
- `research.default_model_class` выбирает класс, если запуск его не переопределил.
- `HERMES_RESEARCH_MODEL_CLASS` выбирает класс для отдельного процесса и наследующих его дочерних стадий.
- Неизвестный класс, неполная запись или отсутствие выбора приводят к отказу до обращения к модели. Скрытого переключения на другой класс или поставщика нет.

```sh
HERMES_RESEARCH_MODEL_CLASS=balanced   "$UDR_PYTHON" "$UDR_SCRIPTS/run_beta_search.py"   --question 'Ваш ограниченный публичный вопрос'   --hermes "$UDR_HERMES"   --output-root "$HERMES_HOME/research-runs" --public-query-ack
```

Переменные пути к исполняемому файлу и каталогу сценариев заданы в [руководстве по процессам](workflows.md). Другой класс выбирается перед новым запуском. Изменение класса или его сопоставления посреди существующего запуска считается изменением условий и отклоняется.

## Совместимость без таблицы классов

Если `research.model_classes` отсутствует, ограниченный вызов использует **фактически загруженные настройки Hermes** `model.provider` и `model.default`. Встроенной запасной пары Nano/OpenRouter нет. Уровень рассуждения берётся из явного `agent.reasoning_effort`, а при отсутствии — `none`. Переменная выбора класса без таблицы классов не принимается.

Так сохраняется работа с уже настроенным Hermes и устраняется список конкретных моделей в исследовательском расширении. Это не обещает поддержку произвольного API: транспорт, реквизиты, адрес службы, мультимодальность и учёт использования должны поддерживаться Hermes.

## Воспроизводимость и учёт

Запуск фиксирует запрошенный класс, происхождение маршрута, отпечаток таблицы сопоставления и фактические поставщика, модель и уровень рассуждения. Перед обращением настройки проверяются повторно. Аргументы процесса, сохранённая попытка и полученный учёт использования должны совпадать. Выбор класса включён в снимок среды.

Квитанция сохраняет **конкретный идентификатор модели из учёта Hermes**, хотя запрос задавался классом. Псевдоним на стороне поставщика может измениться независимо; для строгой воспроизводимости используйте версионированные идентификаторы, если они доступны. Эта запись не удостоверяет внутренние веса удалённой модели. Поэтому два запуска `balanced` различимы после изменения сопоставления оператором. Исторические записи сохраняют прежний маршрут и не переименовываются в исполнения новой модели.

Проверки времени, токенов, числа вызовов и оценок расходов сохраняются. Включённые в подписку оценки обозначаются соответствующим образом; отсутствующий или ненадёжный учёт не становится подтверждённой денежной ценой. Классы не добавляют автоматического резервного переключения, разрешения расходов, фонового поиска новых моделей или ещё одной библиотеки доступа к поставщикам.

## Поля записи маршрута

| Поле | Значение |
|---|---|
| `requested_model_class` | Выбранный класс; `null` для прямого маршрута настроек Hermes |
| `model_class_selection_source` | `environment`, `configured_default` либо `not_applicable` |
| `model_route_source` | `research_model_class` либо `hermes_model_default` |
| `model_class_mapping_hash` | Отпечаток таблицы классов и выбора по умолчанию; `null` без таблицы |
| `provider`, `model`, `reasoning` | Фактический разрешённый маршрут, сверяемый с обращением |

## Обновление набора моделей

1. Выберите модель, доступную через разрешённую настройку поставщика Hermes.
2. Измените сопоставление нужного класса и совместимый уровень рассуждения.
3. Завершите или сверяйте старые попытки в зафиксированных условиях; с новым сопоставлением начинайте новые запуски.
4. Проверьте затронутую возможность и сохраните новый фактический маршрут в квитанции. Исследовательская квалификация и решение о выпуске остаются отдельными.

Установка опубликованного r152 описана в [руководстве](installation.md). Для проверки классов до следующего пакетного выпуска получите текущую `main`, сохраните полный коммит и установите этот точный локальный Git-источник в отдельный домашний каталог Hermes. Это установка исходников разработки, а не подписанного архива r152.

В разработочной `main` прежний формируемый манифест архива не сохраняется с устаревшими хешами. Манифесты выпуска доступны по неизменяемым ссылкам и внутри опубликованной поставки.

```sh
git clone --branch main https://github.com/olegeklepikov-collab/ultra-deep-research.git udr-model-classes
UDR_SOURCE_REF="$(git -C udr-model-classes rev-parse HEAD)"
hermes plugins install "file://$PWD/udr-model-classes" --ref "$UDR_SOURCE_REF" --no-enable
hermes plugins doctor ultra-deep-research --ci
```
